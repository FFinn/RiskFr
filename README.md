# RiskFr — оценка угроз и рисков

Практическая работа по оценке банковского микросервиса: перевод средств между счетами и просмотр истории операций. Исходное приложение сохранено без исправлений.

## Существенное замечание к исходной поставке

Исследована версия `4903ad261d30bc2d1171e455f916e445a7963b4e` [выданного репозитория](https://devsecops.gitlab.yandexcloud.net/devsecops-projects/unit-9-final-practice). Заявленная в задании **SQL-инъекция не подтверждена**: значения передаются отдельно от SQL. Два предупреждения Semgrep относятся к подстановке внутреннего номера параметра и разобраны как ложные срабатывания в части SQL-инъекции. В отчёте это указано явно, с результатами проверок.

При этом подтверждены ошибки проверки личности и денежной логики на уровне функций. Штатному запуску мешают несовпадения имён при импорте и отсутствующий корневой файл сборки контейнера. Эти недостатки не исправлялись: анализ не подменяется доработкой приложения.

## Как открыть модель

В OWASP Threat Dragon 2.6.2 войти в локальный режим, выбрать открытие существующей модели и загрузить `security/model/riskfr.json`. Если окно выбора файла недоступно, вставить содержимое JSON в поле импорта. Открыть диаграмму «Переводы и история операций». При выборе элемента доступны связанные угрозы. Сводка отчёта: **18 угроз, 17 открытых, одна снижена имеющейся мерой**.

PDF подготовлен из сформированной приложением страницы отчёта с русскими подписями и читаемыми карточками вместо широких таблиц. [Копия в HTML](security/reports/threat-dragon-report.html) содержит те же данные.

## Границы выполненной работы

Выполнены анализ кода и архитектуры, запуск Semgrep, проверка правил и вызовы функций на изолированных PostgreSQL и Redis. Подготовлены отдельная ручная находка и файлы загрузки в DefectDojo. Импорт в действующий экземпляр DefectDojo, исправление приложения и проверка исправленной версии не заявляются.

Положительная находка SQL-инъекции остаётся расхождением между условием задания и доступной версией. Для его устранения требуется уточнение исходной поставки у автора задания, а не искусственное внесение уязвимости.
