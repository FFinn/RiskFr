## Результат оценки

Исходная версия — `4903ad261d30bc2d1171e455f916e445a7963b4e` [учебного репозитория](https://devsecops.gitlab.yandexcloud.net/devsecops-projects/unit-9-final-practice). Заявленная в задании **SQL-инъекция не подтверждена**: значения передаются отдельно от текста SQL. Два предупреждения Semgrep относятся к подстановке внутреннего номера параметра и признаны ложными срабатываниями.

Проверками функций подтверждены подмена пользователя, списание сверх остатка при одновременных переводах и повторное списание после отказа Redis.

Для испытаний через HTTP исправлены импорты в `app/main.py` и добавлен `Dockerfile`. Отдельный `compose.check.yml` поднимает приложение с учебной базой. SQL-запросы и проверка личности остались прежними. Через HTTP выполнены 47 запросов: SQL-инъекция не подтвердилась, подмена пользователя воспроизведена. Запросы к базе менять не потребовалось.

## Запуск учебного стенда

```bash
umask 077
if [ ! -f .assessment.env ]; then
  printf 'ASSESSMENT_DB_PASSWORD=%s\n' "$(openssl rand -hex 24)" > .assessment.env
fi
docker compose --env-file .assessment.env -p riskfr-http \
  -f compose.check.yml up -d --build --wait api
```

Описание запросов: [http://localhost:18081/docs](http://localhost:18081/docs). Порядок испытаний и удаления учебной базы приведён в [инструкции](security/REPRODUCE.md).

## Как открыть модель

В OWASP Threat Dragon 2.6.2 выбрать локальный режим и загрузить `security/model/riskfr.json`. Открыть диаграмму «Переводы и история операций». При выборе элемента доступны связанные угрозы. Всего в модели **18 угроз: 17 открытых, одна снижена существующей параметризацией SQL**.

Отчёт доступен в [PDF](security/reports/threat-dragon-report.pdf) и [HTML](security/reports/threat-dragon-report.html).
