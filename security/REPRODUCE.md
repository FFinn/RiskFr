# Повторение проверок

Все команды выполняются из корня репозитория. Приложение не дорабатывается. Не подставляйте рабочую банковскую базу: проверка поведения очищает таблицы только в созданных для неё одноразовых контейнерах.

## Статический анализ

Нужен Python 3.12. Создать отдельное окружение и установить использованную версию:

```bash
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install semgrep==1.184.0
semgrep --test --config security/rules/bank.yml \
  security/checks/rule_cases.py --metrics=off --disable-version-check
semgrep scan --config security/rules/bank.yml \
  --metrics=off --disable-version-check \
  --json --output security/reports/semgrep.json app
```

Ожидаются три успешно проверенных правила, три срабатывания в приложении и пустой массив ошибок. Два предупреждения о динамическом SQL не являются подтверждением SQL-инъекции. Не включайте `security/checks/rule_cases.py` в результаты сканирования приложения: там намеренно находятся искусственные контрольные примеры.

## Проверка поведения

Нужны Docker, Bash и OpenSSL. PostgreSQL и Redis запускаются в отдельной внутренней сети **без публикации портов**. Для базы создаётся случайный пароль. Приложение подключается только к этим контейнерам; исходные файлы монтируются для чтения. После завершения временные контейнеры, их тома, сеть и файл окружения удаляются.

```bash
bash security/checks/run-isolated.sh
```

Первый запуск загружает образы и устанавливает зависимости исходного приложения. `security/checks/Dockerfile` — окружение проверки отдельных функций, а не исправление отсутствующего файла сборки приложения. Результат записывается в `security/reports/behaviour.json`.

Проверяются ошибка импорта приложения; запрет операции при чужом владельце и обход через подмену субъекта; отдельная передача шести строк поиска в параметры SQL; поведение при специально созданном ключе Redis; одновременное чтение остатка двумя операциями; отказ Redis после фиксации и повтор исполнения.

Синхронизация двух чтений и имитация ошибки Redis выполняются только в проверочном окружении. Их назначение — сделать возможный порядок событий воспроизводимым. Текст запросов и функции исходного приложения не исправляются.

## Модель угроз

Открыть `security/model/riskfr.json` в OWASP Threat Dragon 2.6.2 через импорт локальной модели. Проверить наличие четырёх элементов, шести стрелок и трёх пунктирных границ. У пользователя, PostgreSQL и Redis по три угрозы, у API пять. Ещё четыре угрозы прикреплены к потокам.

Открыть отчёт модели. Сводка: 18 угроз, 17 открытых, одна снижена существующей параметризацией SQL. Отчёт можно распечатать в PDF. Приложенный PDF выгружен из сведений этой страницы: подписи переведены на русский язык, широкие строки таблиц представлены карточками; содержание сценариев не заменено.

## Результаты для DefectDojo

- `security/reports/semgrep.json`: тип загрузки `Semgrep JSON Report`.
- `security/reports/manual-idor.json`: ручная карточка для отдельного испытания, тип `Generic Findings Import`; также её можно создать вручную по `security/IDOR.md`.
- Полный порядок обработки приведён в разделе 6 итогового отчёта. Не закрывать ручную находку из-за отсутствия её в повторном отчёте Semgrep.
